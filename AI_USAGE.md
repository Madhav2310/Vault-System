# AI usage

How AI tools were used to design and build this project, including where they were wrong and how that was caught.

## Tools used
- **Claude Code (Claude Opus 5.5 and Sonnet 5.5)**: research, design, implementation, tests, evaluation-set construction, and the cleanup and audit passes.
- **ChatGPT and DeepSeek**: independent reviewers. Their critiques of the plan and of each experiment's results were pasted in and reconciled by the author before anything changed; neither touched the code.
- **OpenAI API (Responses API and embeddings)**: the product's runtime and the evaluation judges. Judges and generator share a vendor, so judged numbers are provisional (`docs/evaluation.md`). An Anthropic adapter exists in the gateway but is dormant.

## Workflow
1. **Design first.** Design (`docs/design.md`) and research passes (`docs/research/01–06`) were written before any code, then cross-reviewed with ChatGPT.
2. **Plan with checks.** `docs/plan/` holds 194 tasks and 792 acceptance criteria. Each criterion is verified by a named test, a command or a manual check. `scripts/plan_lint.py` checks the plan's consistency.
3. **Build one task at a time.** Tests come first, then one commit per task prefixed with the task ID. Evidence goes in `docs/status/progress.md`, and shortfalls and postponed work go in `docs/status/followups.md`.
4. **Claude Code rules.** Project rules in `CLAUDE.md` constrain Claude Code: the gateway-only LLM calls, code-side model routing and citation validation, owner scoping, no content in logs, and the rest.

The design, research, plan and status documents named above were working files. They were removed from the tree before submission and remain in git history (for example `git show 76c8048^:docs/design.md`).

## Per-slice log
### S0
- S0.01–S0.03: repo init, uv/ruff/mypy/pytest skeleton, logs.
- S0.04–S0.22: compose stack, settings, logging, errors, DB schema, auth, repository pattern, object store, LLM gateway, Celery, OpenTelemetry, health, leak guard, eval wiring and spikes. Two tasks were built by parallel subagents in isolated git worktrees (S0.18+S0.21, S0.13); their branches were reviewed and merged by the main session.
- 2026-11-13 provider change: the runtime moved from Anthropic to OpenAI only (no Anthropic key). Claude Code researched current models, pricing, structured outputs, caching and rate limits, ran sub-cent probes on the real key, and rewrote design §4/§5.3/§8.5/§9.1/§13 and the affected plan tasks (new S0.23–S0.25, S4.19).
- S0.23–S0.25 (same day): the OpenAI Responses provider, model roles with the router and a one-attempt role fallback, and a citation spike on 12 sampled smoke items (17 live calls, $0.054 of a $0.50 cap). Live checks are capped samples; the spike's checks read a saved results file so re-running them costs nothing.

## Final outcome
Frozen configuration (code `1c92d64`, gold `81b8b26`): `retrieval@5`, `analyze_query@4`, `answer_rag@12`, `answer_compare@3`, `support_check@1`; judges `eval_judge_claims@4`, `eval_judge_support@3`, `eval_judge_abstain@1`. Against the earlier default re-judged the same way: train audited gold 0.763 to 0.873 (118 items), dev 0.746 to 0.847 (59); the locked benchmark on the original train gold 0.699 to 0.772 (123). The sealed test split was then run once, with no tuning after it (run `01a1db51-9481-7106-8c9c-64e1a87bacd6`, 134 items, draft unaudited gold, $3.41): answer_pass 0.761, faithfulness 0.957, abstention 0.913, citation integrity 1.00, 0 of 11 injection violations, 14 of 14 `must_not_contain` passed, $0.007 and 7.3 s per turn. Commands and the full tables are in `docs/evaluation.md`.
