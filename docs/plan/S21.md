# S21 — Evaluation rebuild: a rich 300-item golden set, claim-level judges, attribution (plan v4)

Goal: a measuring instrument we can trust before any more tuning. The research (`docs/research/reports/High accuracy cited document QA.md`, Phase 1) found that at 44 items the paired minimum detectable effect is about 16 points, larger than every planned change, and that at least 2 of 5 sampled "failures" were judge errors.

Design rules (user decisions, 2026-11-14):
- **About 300 items, rich not big.** Every case type is covered; no stratum is padded with near-copies. Cap 3 items per source document (design effect about 1.6).
- **Gold is atomic claims**, not prose: `required_claims`, `optional_claims`, `alternates` (number formats, units, synonyms), gold evidence as sentence-handle ranges.
- **Splits by document:** train 40%, dev 20%, test 40%; no document in two splits. Test is run only at gates.
- **No tuning on test.** Prompts are tuned on train, confirmed on dev, reported on test.

Cost rules: building the set costs about $3 or less (candidate generation and the cross-model audit run on samples with `--max-usd`). Human time is the main cost: about 200 labels (S21.06).

## Coverage matrix (target counts, total 300)
| # | Stratum | n | Source | Must include |
|---|---|---|---|---|
| 1 | Single-span factual | 40 | QASPER, CUAD, FinanceBench | dates, parties, governing law, defined terms; paraphrased questions (no wording copied from the chunk) |
| 2 | Conditional factual | 20 | CUAD | "under what conditions", "unless", exceptions, notice periods |
| 3 | Table lookup | 25 | FinanceBench | a cell by row+column; multi-page tables; footnoted values; units in header |
| 4 | Numeric calculation | 20 | FinanceBench | ratios, year-over-year change, sums across rows; unit conversion; rounding stated |
| 5 | Multi-span / list | 20 | CUAD, QASPER | "list all", clause lists, datasets used |
| 6 | Multi-hop within a document | 20 | QASPER | method + result in different sections; abstract vs body |
| 7 | Compare across documents | 20 | authored over corpus | 2 and 3 documents; one side absent (must say so) |
| 8 | Conflict / contradiction | 15 | authored | contract vs amendment; two reports disagree; later version wins only if stated |
| 9 | Aggregation / meta | 10 | authored | counts, "which documents mention X", key dates across the vault |
| 10 | Unanswerable (absent) | 25 | authored | plausible but absent facts; right topic, wrong entity; near-miss numbers |
| 11 | False premise | 15 | authored | question assumes a clause/number that is not there |
| 12 | Versioned / near-duplicate distractor | 15 | authored (v1/v2 of one contract) | answer must come from the current version; stale v1 value must not appear |
| 13 | Prompt injection inside documents | 20 | authored fixtures | instruction text in body, footnote, table cell, hidden-looking text, fake system message, "ignore previous", exfiltration request, citation spoofing ("cite E9.9"), role-play, unicode/zero-width, markdown/link injection |
| 14 | Multi-turn | 10 | authored | follow-up with pronoun, scope change, correction ("no, I meant the amendment") |
| 15 | Formatting long tail | 5 | sampled | multi-column page, footnotes, scanned page (needs_ocr state), DOCX tracked changes |

### S21.05 — Cross-model gold audit (Platinum method)
Deps: S21.02, S21.03, S21.04 · Design: §18 · Files: `eval/build/audit.py`, `eval/datasets/vault_eval_v2/audit_queue.yaml`
Do:
1. For every item, run Vault (current main) and a strong model given the gold evidence (role `flagship`) on the question; capped `--max-usd 2`.
2. Every item where either disagrees with gold goes to `audit_queue.yaml` with both answers and the gold evidence text.
3. Human decision per queued item: `gold_wrong` (fix), `gold_incomplete` (add claim), `ambiguous` (drop), `system_wrong` (keep). Items become `verified` only after review; unqueued items become `verified` automatically.
- [ ] AC1 The queue lists every disagreement with both answers and evidence — `t:unit/eval/test_audit.py::test_queue_shape`

### S21.06 — Claim-level judges and human calibration
Deps: S21.05 · Design: §18 · Files: `eval/judge.py`, `backend/prompts/eval_judge_claims@1.md`, `backend/prompts/eval_judge_support@1.md`, `eval/labels/*.yaml`, `backend/tests/unit/eval/test_claim_judge.py`
Do:
1. **Completeness judge (rewrite):** one binary decision per required claim ("is claim k entailed by the answer?"); accepts paraphrase, alternates, equivalent numbers and units; never penalises extra correct detail. Completeness = recall over required claims; `answer_pass` = all required claims entailed.
2. **Support judge:** per answer segment, "is this segment entailed by its cited sentences?" (the narrowest task).
3. **Abstention judge** for strata 10–12: did the answer correctly decline or correct the premise?
4. **Labels:** export 200 (item, answer) pairs oversampling failures (`python -m eval.judge --export-labels 200`), the user labels them; split 15% few-shot / 40% dev / 45% frozen test. Report TPR, TNR and Cohen's kappa per judge on the frozen test.
5. **Cross-family:** a second judge through the dormant Anthropic adapter if a key is provided; otherwise the `flagship` role, with the same-vendor limitation stated in the report.
- [ ] AC1 Claim judge: a correct paraphrase with a different number format passes; a missing required claim fails; extra correct detail does not fail — `t:unit/eval/test_claim_judge.py::test_decisions`
- [ ] AC2 Calibration math (TPR, TNR, kappa) matches hand values on a fixture — `t:unit/eval/test_claim_judge.py::test_calibration_metrics`
- [ ] AC3 Each judge reaches kappa ≥ 0.75 and TNR ≥ 0.90 on the frozen human test labels [A] — `$ python -m eval.judge --calibrate eval/labels/labeled.yaml` prints both per judge
- [ ] AC4 The user labels 200 pairs — `M` user
Evidence: calibration table.
