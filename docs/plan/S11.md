# S11 — Retrieval quality, latency and abstention (plan v2, phase A)

Goal: fix what the eval measured as broken. Hybrid retrieval reaches recall@8 ≥ 0.85, p50 answer latency ≤ 3.5 s (non-streaming), and abstentions are mostly right. Every decision is an A/B on the **train** split with the command that regenerates it, confirmed once on **test**. Nothing is tuned on test items.

Baseline (2026-11-13, `eval/reports/01a1d43d…`, see `docs/plan/v2.md` §2):
- recall@8 is 0.759 per item. Per quote, over stored candidates: RRF 0.445, vector 0.439, after MiniLM rerank 0.348, lexical 0.123.
- p50 latency 5.9 s: analyze_query 2.0 s, generate 2.1 s, embed_query 0.5 s.
- smoke `abstain_precision` 0.50.

Conventions for every task in this file:
- Tests first, with the names in the ACs.
- `make ci && make test` stays green.
- Live calls only with `--max-usd`.
- Each A/B result is appended to `docs/evidence/retrieval_ab.md` as a table row: date, split, config, recall@8, recall@20, mrr@40, p50 retrieval ms, cost, and the exact command.

### S11.08 — Fast path: deterministic routing without `analyze_query`
