# S6 — Document intelligence & living answers

Goal: every ready document gets a quote-verified brief, suggested questions and tags; users get custom summaries, follow-ups and vault-wide key dates; earlier answers are flagged stale when a new version arrives; feedback flows into the eval inbox.

### S6.03 — Fact verification status
Deps: S6.02 · Design: §9.1 · Files: `app/insights/verify.py`
Do: A fact is `verified` iff it has ≥1 citation that resolves to a chunk of the same version **and** its value (normalized) is supported by the cited sentences (string containment for dates, amounts and names; otherwise judge-free token overlap ≥ 0.6). Otherwise `unverified` (dimmed in the UI, excluded from vault views).
- [ ] AC1 Fact with a resolving citation whose sentence contains the value → verified — `t:unit/insights/test_verify.py::test_cited_and_contained`
- [ ] AC2 Fact without citations → unverified — `t:unit/insights/test_verify.py::test_uncited_unverified`
- [ ] AC3 Fact citing a chunk from another version → unverified — `t:unit/insights/test_verify.py::test_foreign_version_unverified`
- [ ] AC4 Date fact whose cited sentence contains a different date → unverified — `t:unit/insights/test_verify.py::test_value_mismatch_unverified`
- [ ] AC5 Corpus-wide verified-fact rate ≥ 0.85 [T] — `t:live/insights/test_brief.py::test_verification_rate`
Evidence: verification rate + 10-fact spot-check table (fact, cited sentence, page) in `docs/evidence/s6_spotcheck.md`.
