# S12 — Document intelligence: the cited brief, summaries, categories (plan v2, phase B)

Goal: the spec's "Smart Document Analysis" and "AI Insights" pillar. Every processed document gets a **DocumentBrief**. Each fact in it cites its source sentence, through the same handle and resolver mechanism as chat, and is marked `verified` only when code confirms the cited text supports it. Users can request custom summaries (length, focus, tone). This is the product's differentiator: insights you can click through to the exact sentence.

Supersedes S6.01–S6.07 (same design §9.1–9.2, re-scoped to these ACs). Runs parallel to S11 (no shared files except `app/ingestion/runner.py` STAGE_ORDER, owned by S12.04).

Conventions:
- Every prompt is a versioned file with an entry in the `AI_USAGE.md` prompt log (version, change, measured effect).
- Model calls only through the gateway, requesting a role.
- Live samples run with `--max-usd`.
- No document text in logs.

### S12.01 — Brief schema and fact model
Deps: S3.09 · Design: §9.1 · Files: `app/insights/brief.py`
Do: Pydantic, strict-mode compatible (every field required, `T | None` only). The model output is `BriefOut{document_type, summary, category, tags[], suggested_questions[], facts[]}` with:
- `facts[]{field, value, evidence[]}`
- `field` ∈ {party, effective_date, expiry_date, deadline, amount, obligation, termination, governing_law, key_point, risk, other}

Caps: summary ≤ 1,200 chars; ≤ 40 facts; ≤ 8 tags (lowercase, 1–3 words); 3–6 suggested questions; category from a fixed enum (contract, financial_report, research_paper, policy, correspondence, other). Code-side, the stored `Brief` holds resolved facts with `EvidenceReference`s and a `status: verified|unverified`.

### S12.03 — Fact verification
Deps: S12.01 · Design: §9.1 · Files: `app/insights/verify.py`
Do: A fact is `verified` iff it has ≥ 1 resolved citation into the same version and the value is supported by the cited sentences:
- dates: the normalized date (ISO) appears in the cited text in any common format
- amounts: the numeric value with currency or percent appears after normalizing separators
- names / parties: case-insensitive token containment ≥ 0.8
- other fields: content-token overlap ≥ 0.5 after stopword removal

Otherwise the fact is `unverified`, with a reason code (`NO_CITATION`, `VALUE_NOT_IN_CITATION`). Pure functions only.
- [x] AC1 Date fixtures: "June 1, 2020" cited for value "2020-06-01" → verified; "2021-06-01" → unverified — `t:unit/insights/test_verify.py::test_dates`

### S12.04 — Brief stage: map-reduce, `enriched` status, cost cap
Deps: S12.02, S12.03 · Design: §6.2, §6.3, §9.1 · Files: `app/insights/stage.py`, `app/ingestion/runner.py`, `app/ingestion/stages.py`, `app/ingestion/jobs.py`
Do: A new stage `brief` after `index` (STAGE_ORDER), on the AI queue.
- **Single call** when the document's chunks fit `BRIEF_MAX_EVIDENCE_TOKENS` (default 12,000).
- **Map-reduce** otherwise: groups of whole sections up to the budget, then one `brief_merge@1` call (role `fast`, strict schema). The merge receives the map outputs as plain JSON, not document text. Facts are deduplicated by `(field, normalized value)` and citations are kept from the map step.
- **Cost cap** per document: `BRIEF_MAX_USD` (default 0.05). Exceeding it stops further map calls and merges what exists, with reason `BRIEF_PARTIAL_BUDGET`.
- **Storage:** `document_insights` row `kind='brief'`, `params_hash` of `{}`, `prompt_version=1`, `content` = stored Brief JSON, `model` = resolved model.
- **Version status:** moves `ready` → `enriched` on success. A brief failure leaves it `ready`, sets `error_code` on the insights row only, and never fails the document.
- **Idempotent:** a rerun with an existing row for the same key does nothing.
- [x] AC1 A small document produces exactly one `brief_extract` call and one `document_insights` row — `t:integration/insights/test_brief_stage.py::test_single_call`
- [x] AC2 A document over the budget produces N map calls plus 1 merge call, and duplicate facts across groups appear once — `t:integration/insights/test_brief_stage.py::test_map_reduce_dedup_facts`
- [x] AC3 Facts keep valid citations after the merge (every `chunk_id` belongs to the version) [A] — `t:integration/insights/test_brief_stage.py::test_merge_keeps_citations`
- [x] AC4 The version becomes `enriched` after the stage and `GET /documents/{id}` shows `enriched` — `t:integration/insights/test_brief_stage.py::test_enriched_status`
- [x] AC5 A provider failure leaves the version `ready` (not failed), the job completes, and the insights row has `status='failed'` — `t:integration/insights/test_brief_stage.py::test_failure_isolated`
- [x] AC6 Hitting `BRIEF_MAX_USD` stops further calls and stores a partial brief with `BRIEF_PARTIAL_BUDGET` — `t:integration/insights/test_brief_stage.py::test_cost_cap`
- [x] AC7 Rerunning the stage for the same version makes zero provider calls — `t:integration/insights/test_brief_stage.py::test_idempotent_rerun`

### S12.06 — Custom summaries
Deps: S12.05 · Design: §9.2 · Files: `app/insights/summaries.py`, `backend/prompts/summary_custom@1.md`, `app/api/documents.py`
Do: `POST /v1/documents/{id}/summaries {length: short|medium|long, focus?: str ≤ 200, tone?: neutral|executive|plain}`.
- **Response:** 200 with the summary if cached for `(version, params_hash, prompt@v)`, else 202 `{status: pending, poll: /v1/documents/{id}/summaries/{summary_id}}` and a Celery task on the AI queue.
- **Output:** segments with citations (the answer segment schema). Length targets: short ≤ 80 words, medium ≤ 200, long ≤ 450.
- **Large documents:** the evidence is the top chunks retrieved for the focus (or for "overview" without focus), up to 12k tokens, so a large document never fails.
- **Focus text** is user input placed in a delimited block (injection-safe).
