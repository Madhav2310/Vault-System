# S18 — Chat experience API: streaming, explainability, follow-ups, compare, quotas (plan v3)

Goal: the API a UI needs for a great experience:
- answers stream with live status, citations and support flags
- every answer can explain itself ("why this answer")
- follow-ups, comparisons and questions about the vault itself work
- cost and abuse are bounded

Read `docs/plan/v3.md` first. Carried from v2: S13.01–S13.09 and S14.02, S14.04, S14.06 AC4–AC5, S14.07. Their full v2 text in `docs/plan/S13.md` and `docs/plan/S14.md` is the reference where this file says "as S13.xx". **Where they differ, this file wins.**

Verified fact (S3.08 live test, 2026-11-13): the OpenAI Responses API streams our strict-schema answer as partial JSON, and `app/chat/segments_reader.py` already parses completed segments incrementally. Streaming needs no new provider work.

### S18.01 — SSE turn stream: events and transport
Deps: S17.13 · Design: §8.6 · Files: `backend/app/api/chat.py`, `backend/app/chat/events.py`, `backend/app/chat/graph.py`, `backend/app/chat/nodes/*.py`, `backend/tests/integration/chat/test_turn_stream.py`
Do:
1. **Accept header.** `POST /v1/chat/sessions/{id}/messages` with `Accept: text/event-stream` streams events; JSON mode is unchanged.
2. **Events come from the graph** (S17.14): the node runner emits `status` when a node starts (a mapping from node name to stage lives in `events.py`), and the `generate` and `verify` nodes emit `segment` and `verification`. All emits go through an `EventSink` protocol:
   - `async def emit(self, event: TurnEvent) -> None`
   - `NullSink` for JSON mode, `QueueSink` (an `asyncio.Queue`) for SSE.
3. **`TurnEvent`** is a pydantic discriminated union on `type`. Every event carries `run_id`.

   | Event | Fields | When |
   |---|---|---|
   | `run.started` | `message_id` | first |
   | `status` | `stage`: analyzing, retrieving, reading_documents, checking_evidence, writing, verifying, saving | stage changes |
   | `segment` | `index, text, support, evidence[]` | each segment, once it is complete and resolved |
   | `verification` | `verdicts[{index, verdict}]` | after the S17.09 support check |
   | `followups` | `questions[]` | S18.04 |
   | `done` | `message_id, response_type, reason_codes, usage{input_tokens, output_tokens, cost_usd}, latency_ms, ttft_ms` | end |
   | `error` | `code, retryable` | failure |

   `segment.evidence[]` carries `chunk_id, document_id, document_title, version_no, pages|null, sentence_start, sentence_end, cited_text`.
4. **Transport:**
   - Use `sse-starlette` if it is a dependency; otherwise a `StreamingResponse` with `text/event-stream`. The main session adds the dependency if the lane requests it.
   - Heartbeat comment every 15 s and header `X-Accel-Buffering: no`.
   - The turn keeps running if the client disconnects (the existing `asyncio.shield` pattern).
5. **Schema:** the event schema is exported in OpenAPI via a documented `GET /v1/chat/events/schema` (JSON Schema of the union), so the UI can generate types.

- [ ] AC3 `done.message_id` equals the stored assistant message, and the streamed segments equal the persisted segments and evidence exactly [A] — `t:integration/chat/test_turn_stream.py::test_stream_equals_persisted`
- [ ] AC4 Headers include `text/event-stream` and `x-accel-buffering: no` — `t:integration/chat/test_turn_stream.py::test_headers`

### S18.03 — "Why this answer": the run explanation endpoint
Deps: S18.01 · Design: §10 · Files: `backend/app/api/runs.py`, `backend/app/explain/views.py`, `backend/app/explain/templates.py`, `backend/app/main.py`
Do:
1. **`GET /v1/runs/{run_id}`** (owner-scoped) returns:

   ```
   {status, mode, route, response_type, reason_codes,
    explanation: [str],
    sources: [{document_title, version_no, pages, chunks_used}],
    steps: [{node, status, duration_ms}],
    usage: {calls, input_tokens, output_tokens, cost_usd},
    message (if finished)}
   ```
2. **`explanation`** is rendered by **templates from reason codes and run facts, never by a model**. Examples:
   - "Answered from 3 passages in 'Consulting Agreement' v1."
   - "Read the whole document (2 documents, 18k tokens)."
   - "One sentence is not supported by its citation."
   - "Nothing in your documents matched closely enough."
3. **Templates:** one per reason code in `templates.py`. A unit test fails if a reason code used anywhere in `app/` has no template (grep the constants).
4. **Content limits:** no prompts, no model names, and no document text except `cited_text` already in the message.
- [ ] AC1 A finished run returns all fields; another owner's run → 404 — `t:integration/explain/test_runs_view.py::test_shape_and_owner`
- [ ] AC2 Every reason code constant in `app/` has a template — `t:unit/explain/test_templates.py::test_all_codes_templated`
- [ ] AC3 The explanation for a full-context run mentions the document count and tokens; a gate abstention mentions "Nothing … matched" — `t:integration/explain/test_runs_view.py::test_explanations`
- [ ] AC4 No model name or prompt id appears in the response (string scan) — `t:integration/explain/test_runs_view.py::test_no_internal_leak`
- [ ] AC5 Running → `status: running` (used for reconnect) — `t:integration/explain/test_runs_view.py::test_running_state`
