# S13 — Chat experience: streaming, follow-ups, compare, meta, grounding baseline (plan v2, phase C)

Goal: chat feels fast and smart. Answers stream with live status and citations, offer follow-up questions, compare documents side by side, answer questions about the vault itself from data, and the answer quality is measured and frozen.

Supersedes S5.01–S5.05, S4.03–S4.05, S4.07, S4.12, S6.08 and S3.15 (same design sections, re-scoped). Phase C runs after S11.08, because the turn orchestrator shape must be stable.

Conventions: as S11. SSE uses `sse-starlette` (design §8.6). If it is not yet a dependency, the lane requests it: the main session edits `pyproject.toml`.

### S13.01 — SSE turn stream: event schema and transport
Deps: S11.09 · Design: §8.6 · Files: `app/api/chat.py`, `app/chat/events.py`, `app/chat/turn.py`
Do: `POST /v1/chat/sessions/{id}/messages` with `Accept: text/event-stream` streams events. Every event is JSON with `run_id`:
- `run.started{message_id}`
- `status{node: analyzing|retrieving|checking|generating|saving}`
- `segment{index, text, support, evidence[]}`, sent when a segment's evidence closes
- `followups{questions[]}` (S13.05)
- `done{message_id, response_type, reason_codes, usage{input_tokens, output_tokens, cost_usd}, latency_ms, ttft_ms}`
- `error{code, retryable}`

The orchestrator emits through an `EventSink` protocol (a no-op sink for JSON mode). Transport details:
- heartbeat comment every 15 s
- header `X-Accel-Buffering: no`
- the event schema is a pydantic union, documented in OpenAPI

JSON mode (no Accept header) is unchanged.
- [ ] AC1 Event order for a FakeProvider answer is `run.started`, ≥ 1 `status`, ≥ 1 `segment`, `done` — superseded by S18.01 AC1 (plan v3)
- [ ] AC2 Every event validates against the event union schema — superseded by S18.01 AC1 (plan v3)
- [ ] AC3 The `done.message_id` equals the assistant message in history — superseded by S18.01 AC1 (plan v3)
- [ ] AC4 Response headers include `content-type: text/event-stream` and `x-accel-buffering: no` — superseded by S18.01 AC1 (plan v3)
- [ ] AC5 A heartbeat comment arrives within 15 s of an idle generation (FakeProvider latency 16 s; test clock patched) — superseded by S18.01 AC1 (plan v3)
- [ ] AC6 JSON mode returns the same assistant content as SSE mode for the same scripted reply — superseded by S18.01 AC1 (plan v3)
- [ ] AC7 A retried `client_message_id` over SSE for a finished turn streams a single `done` with the stored message (no re-run) — superseded by S18.01 AC1 (plan v3)
Evidence: recorded event transcript in `docs/evidence/sse_transcript.txt`.

### S13.06 — Meta route: questions about the vault, answered by SQL
Deps: S12.05 · Design: §8.3, §10.1 · Files: `app/chat/meta.py`, `app/chat/turn.py`, `backend/prompts/analyze_query@2.md`
Do: When analyze returns `intent=meta`, it also returns a typed `meta_op` from an allowlist. Each op is a parameterized owner-scoped SQL query; the LLM never writes SQL.
- `COUNT_DOCUMENTS{status?, category?}`
- `LIST_DOCUMENTS{category?, tag?, limit ≤ 20}`
- `DOCUMENTS_MENTIONING{term}` (lexical search grouped by document)
- `LIST_KEY_DATES{field?, before?, after?}` (from brief facts)
- `DOCUMENT_INFO{document_ref}` (pages, status, versions, category)

The answer is a template rendering of the rows, with segments whose evidence links to brief facts where applicable. The intent schema bumps to `analyze_query@2`.
- [ ] AC1 "How many documents do I have?" → `COUNT_DOCUMENTS` → the exact count, zero generate calls — superseded by S18.05 AC1 (plan v3)
- [ ] AC2 "Which documents mention Delaware?" lists exactly the owner's documents containing the term — superseded by S18.05 AC1 (plan v3)
- [ ] AC3 "List contracts expiring before 2025" uses brief facts `expiry_date` and renders cited dates — superseded by S18.05 AC1 (plan v3)
- [ ] AC4 An op outside the allowlist from the model → falls back to the qa route with reason `META_OP_REJECTED` — superseded by S18.05 AC1 (plan v3)
- [ ] AC5 Every meta SQL statement filters by `owner_id` (another owner's documents never counted) — superseded by S18.05 AC1 (plan v3)
- [ ] AC6 Both meta eval items pass `meta_correct` — superseded by S18.05 AC1 (plan v3)
Evidence: transcripts.

### S13.07 — Compare route (multi-document)
Deps: S11.06 · Design: §8.3, §8.4 · Files: `app/chat/compare.py`, `backend/prompts/answer_compare@1.md`, `app/retrieval/retrieve.py`
Do: When analyze returns `intent=compare` with ≥ 2 target documents (or the scope has 2–5 documents), retrieve **per document** with `top_n_per_doc = max(3, 8 // n_docs)`. Build one evidence set in which each document's chunks are grouped under a document header. Generate with `answer_compare@1`: one paragraph per dimension, each side cited, an explicit "not found in X" sentence when a document lacks evidence, and no tables. With more than 5 documents the turn falls back to qa with reason `COMPARE_TOO_MANY`.
