# S19 — Web UI: library, source guide, streaming chat with exact citations (plan v3)

Goal: a small, polished UI that makes Vault's strengths visible in 60 seconds:
- upload with live status
- a cited "source guide" per document (summary, key facts, suggested questions)
- streaming chat whose citation markers show the exact sentence on hover and open it highlighted on click
- clear "not found", "no citation" and "unsupported" states
- a "why this answer" panel

Patterns from research (report §1): numbered markers, a hover card with the exact quote, a click-through to the highlighted passage, a source guide on upload, and explicit not-found handling.

Stack: Vite + React + TypeScript, served by FastAPI at `/app` from `frontend/dist`. Auth is an API key typed on a settings screen and kept in `localStorage`; this is a documented demo assumption. Plain CSS with tokens, no component library. Keyboard reachable, with visible focus and labels.

Machine rules: `npm` installs and builds are heavy. Never run them in parallel with a test suite. Playwright runs headless Chromium: run `make ui-e2e` only on an idle machine, and close it after.

Supersedes S15.01–S15.05. Their text in `docs/plan/S15.md` is a reference; **this file wins**.

### S19.01 — Frontend scaffold, typed client, serving
Deps: S18.01, S18.03 · Design: §2 · Files: `frontend/` (new), `backend/app/main.py`, `Makefile`, `backend/Dockerfile`
Do:
1. **Scaffold** `frontend/` with Vite React TS: `src/api/client.ts`, `src/api/types.ts` and `src/sse.ts`.
   - `types.ts` is generated by `openapi-typescript` from `/openapi.json` plus `/v1/chat/events/schema` (S18.01).
   - `client.ts` attaches the API key header and maps `ErrorResponse` to typed errors.
   - `sse.ts` is a fetch-based SSE reader (POST plus stream; `EventSource` cannot POST).
2. **Make targets:**
   - `make ui`: `npm ci && npm run build` in `frontend/`.
   - `make ui-types`: regenerate types.
   - `make ui-types-check`: diff the generated types against the committed ones; non-zero when stale.
3. **Serving.** FastAPI mounts `frontend/dist` at `/app` when the folder exists, with SPA fallback to `index.html`. When it is absent, `/app` → 404 and nothing else changes.
4. **Docker.** A multi-stage api Dockerfile: a node build stage copies `dist` into the image.
5. **CI.** `make ci` additionally runs `npm run typecheck` and `npm run lint` when `frontend/node_modules` exists. It prints "frontend skipped" otherwise, so CI stays Docker-free and fast.

### S19.04 — Document page: source guide and source viewer
Deps: S19.03, S12.05 · Design: §2, §9.1 · Files: `frontend/src/document/*`, `frontend/src/source/*`
Do:
1. **Source guide card,** from the brief: summary, document type, tags, key facts grouped by field with a citation marker each, unverified facts labelled "unverified" in text (not only colour), and suggested questions as chips that start a chat scoped to this document.
2. **Source viewer** (a shared component used by chat as well):
   - It fetches `GET /v1/chunks/{id}` and renders the chunk text with the cited sentence range highlighted, using `sentences[sentence_start..sentence_end)` offsets. It never searches for strings.
   - It shows the document title, version, page(s) (none for flow documents) and section path.
   - Previous and next chunk navigation.
3. **Custom summary control:** length, tone and focus. Shows pending, then the cited summary.

### S19.05 — Chat: streaming, exact citations, trust states
Deps: S19.04, S18.03, S18.04 · Design: §2, §8.6 · Files: `frontend/src/chat/*`
Do:
1. **Layout:** a session list, new chat, and a scope picker (all documents or selected).
2. **Streaming:** a status line from `status` events in plain language ("Searching your documents…", "Reading 2 documents…", "Writing…", "Checking citations…"). Segments render as they arrive.
3. **Citations:**
   - Numbered markers `[1]` per distinct evidence item.
   - **Hover or focus** shows a card with the exact `cited_text`, the document title and page.
   - **Click** opens the source viewer (S19.04) with the highlight.
4. **Trust states:**
   - A segment with `support=none` shows a subtle "no citation" tag.
   - `verification=unsupported` shows "not supported by its source", with the reason on hover.
   - An abstention renders a "Not found in your documents" card with suggested questions.
   - Conflicts render as a callout citing both sides.
   - A stale answer shows a banner with "Re-ask on v{n}".
5. **"Why this answer?"** link opens a panel from `GET /v1/runs/{id}`: the explanation list, sources, steps with timings, and cost.
6. **Follow-up chips. Errors:** 409, 429 (with the retry time), 503 and network errors show friendly messages; the input text is kept.
