# S1 — Ingestion with geometry

Goal: any supported file becomes a `ready` version with sentence-aware chunks, page geometry, embeddings and full-text vectors. Every failure path yields a precise status, and recovery is automatic and idempotent.

Test conventions: integration tests run against the compose Postgres/Redis; Celery runs eagerly **only** in unit tests. Integration tests use real workers.

### S1.09 — Stage runner, retries, dead state (+ job_events retention)
Deps: S1.08 · Design: §6.3, §6.6, §11 · Files: `app/ingestion/runner.py`, `app/ingestion/errors.py`
Do:
- Run the current stage; on success, one transaction replaces the stage's outputs, advances `current_stage`, appends `job_events`, then dispatches the next stage.
- Errors are classified permanent or retryable. Backoff = `min(2^attempt × 10 s, 10 min)` ± 20% jitter. `max_attempts=5` → `dead` and version `failed`.
- `job_events` older than 90 days purged daily.
- [x] AC1 Successful stage writes one `job_events` row with `duration_ms` and advances the stage — `t:integration/ingestion/test_runner.py::test_stage_success_event`
- [x] AC2 Re-running a completed stage replaces outputs (row count unchanged) — `t:integration/ingestion/test_runner.py::test_stage_rerun_idempotent`
- [x] AC3 Retryable error sets `next_attempt_at` within the backoff window and `attempt_count+1` — `t:integration/ingestion/test_runner.py::test_retryable_backoff`
- [x] AC4 Permanent error sets the terminal status immediately with `error_code` — `t:integration/ingestion/test_runner.py::test_permanent_error_terminal`
- [x] AC5 Fifth retryable failure → job `dead`, version `failed`, `error_code` set — `t:integration/ingestion/test_runner.py::test_dead_after_max_attempts`
