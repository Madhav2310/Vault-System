### S14.01 — Per-user request rate limit
Deps: S3.04 · Design: §13.4 · Files: `app/core/ratelimit.py`, `app/api/deps.py`, `app/core/settings.py`
Do: A Redis token bucket per (user, bucket):
- `chat_post` 20/min
- `upload` 30/min
- `default` 300/min

Implemented as a Lua script, atomic. Responses carry `X-RateLimit-Limit`, `X-RateLimit-Remaining` and `X-RateLimit-Reset`. Over the limit → 429 `rate_limited` with `Retry-After` (seconds) and `retryable: true`. Redis down → fail open, with a warning log and metric `vault.ratelimit.fail_open`. Limits come from settings.

- [x] AC2 Headers present and `Remaining` decrements on each request — `t:integration/core/test_ratelimit.py::test_headers`
- [x] AC3 Buckets are per user (user B unaffected by user A's exhaustion) — `t:integration/core/test_ratelimit.py::test_per_user`
- [x] AC4 Redis unavailable → requests succeed (fail open) — `t:integration/core/test_ratelimit.py::test_fail_open`
- [x] AC5 Concurrent requests never exceed the limit (50 parallel requests with limit 20 → exactly 20 succeed) — `t:integration/core/test_ratelimit.py::test_atomic_under_concurrency`

### S14.02 — Daily LLM cost quota per user
Deps: S14.01 · Design: §13.4 · Files: `app/core/quota.py`, `app/chat/turn.py`, `app/metrics/chat.py`
Do: The user's spend today is `sum(llm_calls.cost_usd)` since UTC midnight, cached in Redis for 30 s. Each user has a quota (setting `USER_DAILY_USD`, default 1.00; admins unlimited). Before a turn or a summary request, if spend ≥ quota → 429 `quota_exceeded` with `Retry-After` set to the seconds until UTC midnight. Ingestion is never blocked (documents stay usable); briefs over quota are deferred with status `quota_deferred` and retried by beat after the reset. `/v1/metrics/chat` shows `quota {limit_usd, spent_today_usd}`.

### S14.03 — Upload a new version of a document
Deps: S1.27 · Design: §6.1, §6.2, §12 · Files: `app/api/documents.py`, `app/documents/service.py`
Do: `POST /v1/documents/{id}/versions` (multipart `file`, `Idempotency-Key`) creates `version_no = max + 1` and starts processing. When the new version becomes ready, `current_version_id` moves (existing index stage behaviour), the old version becomes `superseded`, and new chat scopes use the new version. Identical bytes to the current version → 200 `deduplicated: true` with no new version. Wrong owner or deleted document → 404.

### S14.05 — Live processing status (SSE)
Deps: S1.27 · Design: §12 (`/processing/stream`) · Files: `app/api/versions.py`, `app/ingestion/events.py`
Do: `GET /v1/versions/{vid}/processing/stream` sends one `stage{name, status, at}` event per `job_events` row (catch-up first, then live via Redis pub/sub published by the runner on each stage commit), then a terminal `done{status}`. It closes on a terminal status, with a heartbeat every 15 s and a 10 min max lifetime.
