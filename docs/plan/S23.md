# S23 — Warm voice and a seamless chat (plan v4, added 2026-11-14)

Goal: the chat reads like a calm, kind colleague who knows the documents, and the human stays in control without friction. Found gaps (2026-11-14): no voice guidance exists (answer prompts say "answer first, plain, precise"; refusals are fixed machine templates); no stop button, regenerate, edit-and-resend, copy-with-citations, or clarifying question.

Rules: voice changes are new prompt versions or template edits, accepted only if faithfulness and citation precision are non-inferior in a paired A/B on dev (warmth must never loosen grounding). UI uses the Lucin tokens already in `frontend/src/tokens.css`; every interaction works by keyboard, respects reduced motion, and has e2e + axe coverage.

### S23.01 — Voice guide and warm templates
Deps: S22.04 · Design: §8 · Files: `backend/prompts/voice@1.md`, `backend/app/chat/voice.py`, `backend/app/explain/templates.py`, `docs/voice.md`
Do:
1. `docs/voice.md`: the voice in one page: calm, warm, direct; short sentences; says what it found and what it did not, kindly; never blames the user; no corporate filler, no exclamation marks, no emojis; same language as the user; does not over-apologise; numbers and names stay exact. Includes 6 before/after examples (answer, partial, not found, ambiguous, conflict, error).
2. `voice@1.md` is a prompt fragment appended by code to the answer prompts (answer_rag, answer_compare, meta) via `voice.py` (version recorded in the run). It changes tone only: no new facts, citation rules untouched.
3. Rewrite user-facing templates (abstain, not found, quota, conflict, errors, stale answer) in the same voice, each with a "what you can do next" line. Reason codes unchanged.
- [ ] AC1 Every user-facing template follows the guide: a test checks no template contains banned patterns (exclamation, "I'm sorry" twice, "Error:", "invalid", all-caps words) and each abstain/not-found template contains a next step — `t:unit/explain/test_voice_templates.py::test_templates_warm`
- [ ] AC2 Prompt fragment is appended, versioned, and never changes citation rules (golden prompt snapshot test) — `t:unit/chat/test_voice.py::test_fragment_appended`
- [ ] AC3 Paired A/B on dev: faithfulness and citation precision non-inferior (lower CI bound > −2 points) — `$ grep -c "voice@1" docs/evidence/s22_ab.md` ≥ 1
Evidence: A/B rows, before/after examples.

### S23.02 — Clarify when ambiguous (human in the loop)
Deps: S22.04 · Design: §8.2 · Files: `backend/app/chat/nodes/run_analyze.py`, `backend/app/chat/clarify.py`, `frontend/src/chat/ClarifyChips.tsx`
Do: the analysis step may return `clarification: {question, options[≤4]}` only when code-checked ambiguity holds (question matches several documents/versions with no scope, or a pronoun with no antecedent and no history). The turn ends with a `clarify` event (no model-written answer); the UI shows option chips; choosing one posts a normal turn with scope/context resolved by code. Never more than one clarification in a row; the second turn always answers.
- [ ] AC1 Ambiguous multi-document question yields a clarify event with options that are real documents; the follow-up turn answers — `t:integration/chat/test_clarify.py::test_clarify_then_answer`
- [ ] AC2 No clarification loop (second turn always answers) and unambiguous questions never clarify — `t:integration/chat/test_clarify.py::test_no_loop`
Evidence: test output.

### S23.03 — Chat interaction polish (UI)
Deps: S22.11 · Design: §19 · Files: `frontend/src/chat/*`, `frontend/src/app.css`, `frontend/src/chat/chat.css`
Do (Lucin look; follow the design-router skills; no new dependencies):
1. **Stop** button while streaming (aborts the stream, keeps the partial text marked "stopped"); **Regenerate** on the last answer (reuses scope; new client_message_id); **Edit and resend** the last question; **Copy answer** with numbered citations and quotes.
2. Streaming feel: segments fade in, citation markers appear after the verification event, skeleton before first token, scroll-follow that pauses when the user scrolls up and offers "Jump to latest".
3. Feedback: thumbs plus optional reason chips (wrong, incomplete, bad citation, too long); a "Wrong document?" nudge that opens the scope picker.
4. Empty states and suggestions: first-run suggested questions from the document brief; follow-up chips always visible after an answer; keyboard: Enter send, Shift+Enter newline, Esc stop, ↑ edit last.
5. Warm microcopy everywhere in the UI per `docs/voice.md`; skeleton and error states instead of spinners and raw errors; `prefers-reduced-motion` honoured.
