# Plan v3: execution guide (read this first)

Plan of record from 2026-11-13 (user decision). It replaces the unfinished parts of v2 (S11, S13, S15). Done work in S0–S15 stays as it is. Slices: **S16 → S17 → S18 → S19 → S20**.

Rationale: `reports/Vault rebuild strategy research.md` (research), `docs/plan/v2.md` (earlier assessment) and the root-cause notes in §6 below. Status: `docs/STATUS.md`.

## 1. What v3 changes, and why

| Change | Evidence |
|---|---|
| Fix the dev environment first: compose profiles, memory limits, Docker off by default | Docker made the user's Chrome crash. The Docker VM hit about 570% CPU and about 8 GB of memory. |
| **Fix the reranker by root cause, not by replacing it** | The service used 10 ONNX threads (P- and E-cores), batch size 64 and full 512-token passages. On an idle M4 that measured 1.0 s and 1.5 GB for 40 passages. 4 threads, batch 8 and ~240-token windows measured 288 ms and 343 MB; with 20 passages, 142 ms. See §6. |
| Never measure the reranker while it degrades | It timed out in 79% of eval runs, so earlier reranker numbers measured plain fusion. |
| **Whole-document answering for small scopes** | Self-Route: 49.7 vs 37.3. FinanceBench: 79% full context vs 19% shared vector store (research report §3). |
| **Check that cited sentences support each answer segment** | Up to 57% of RAG citations are "correct but unfaithful" (Wallat et al.). Code-copied citations stop fake quotes, not unsupported claims. |
| Contextual chunk headers (index side only) | Anthropic: −35% to −49% retrieval failures (vendor numbers, so A/B tested here). |
| Paired statistics for every A/B | 122 items gives about ±7–8 points; only paired tests detect small changes. |
| UI, README and demo earlier and better | Reviewers spend 5–20 minutes, run it first, and miss docs in 80% of submissions. Our best asset (exact citations) is invisible without a UI. |
| Cut: convergence engine stages, matrix, load tests, Grafana dashboards, geometry vision QA | Low visibility for their cost; over-engineering is penalized. |

## 3. Environment rules (non-negotiable)

1. **Docker is off unless a task needs it.**
   - Unit tests and lint (`make ci`) need no Docker.
   - Integration tests need only Postgres and Redis: `make up-test` (S16.01).
   - Only the e2e, live-pipeline and UI tasks need `make up`.
   - Run `make down` when you finish a Docker-needing task.
2. **One heavy command at a time.**
   - Heavy means a full test suite, an eval run, ingestion of the corpus, or the reranker benchmark.
   - Check `uptime` first. If the 1-minute load is above 8, wait.
   - Never loop full evals. Use the `train` split, `eval.replay` or targeted tests.
3. **Targeted tests while developing:** `cd backend && <env> uv run --frozen pytest path/to/test.py::test_name -q`. Run the full gates (`make ci`, then `make test`) once, at the end of the task.
4. **Live model calls:** always behind a `--max-usd` cap, or a test with a hard-coded cost cap. Record cost in `docs/progress.md`. Keys live only in `.env`.
5. **Never** run `make up` or `make down` inside a lane. Lanes use `make up-test` services that the main session started.

## 5. Definition of done (every task)

1. Read the task, its `Design:` sections and the files it lists. Read the code you change before changing it.
2. Write the named tests first. A test name in an AC is a contract: same file, same function name.
3. Implement the smallest complete change. Never weaken an [A] criterion. If a [T] target is not met, record the measured value in `docs/progress.md` and stop for the user.
4. Run the targeted tests, then `make ci`, then `make test` if the task touches DB or integration code.
5. Tick the ACs with `scripts/plan_tick.py` only with evidence. Append a `docs/progress.md` entry (date, task, what, evidence numbers and commands, cost). Add an `AI_USAGE.md` prompt-log row for any prompt change.
6. Commit once per task. The message starts with the task ID (e.g. `S16.02: ...`) and ends with the attribution line given by the session.
7. **Two attempts, then stop.** If a fix fails twice, write the root cause analysis (symptom, hypothesis, test, result) in `docs/progress.md` and ask. Never guess silently.

## 6. Root-cause notes (measured 2026-11-13, idle M4, native, fastembed 0.x, MiniLM-L6 ONNX)

**Reranker latency.** Per-request latency for 40 passages with batch 64, by passage length and thread count:

| passage length | 1 thread | 2 threads | 4 threads | 10 threads |
|---|---:|---:|---:|---:|
| ~513 tokens | 1596 ms | 1194 ms | 858 ms | 1031 ms |
| ~243 tokens | 543 ms | 419 ms | 324 ms | 406 ms |
| ~121 tokens | 256 ms | 191 ms | 148 ms | 210 ms |

- **Too many threads hurt:** 10 is worse than 4, because the M4 has 4 performance cores and 6 efficiency cores.
- **Passage length dominates** (attention cost is quadratic).
- **Batch size 8 vs 64:** 4 threads, ~243 tokens, 40 passages measured 288 ms with peak RSS 343 MB. With 513 tokens and batch 64 the RSS was 1540 MB.
- **The service shipped the bad configuration:** `threads = os.cpu_count()` (10), `ThreadPoolExecutor(10)`, batch 64, and passages up to 8,000 chars. The eval measurements ran under load average 20+.
- **Fix:** S16.02 and S16.03.

**PDF extraction.** The AMD 10-K (121 pages, 420k chars) takes 37 s CPU and 720 MB peak RSS in a native run. A 1 GB worker limit killed it (worker process plus extraction subprocess). The fix is S16.05.

**Docker / Chrome crash.** The host has 16 GB RAM. The Docker VM was using about 8 GB (the reranker 3.1 GB, otel-lgtm 0.9 GB), plus Chrome. The fix is S16.01 (profiles plus memory limits); the user also sets Docker Desktop memory (S16.01 AC5).

## 7. Codebase map (what exists; reuse it, don't fork it)

- **API**
  - Routes: `backend/app/api/{documents,versions,chunks,chat,metrics,feedback,health}.py`
  - Errors: `DomainError(ErrorCode.X)` from `app/api/errors.py` and `app/core/error_codes.py`
- **Ingestion**
  - Stages: `app/ingestion/{runner,stages,embed_index,chunk,sentences}.py`. `STAGE_ORDER` is extract, quality, chunk, embed, index, brief.
  - Extraction: `app/ingestion/extract/*`
  - Job state: `processing_jobs` with leases. Every stage is idempotent with a fenced commit.
- **Retrieval:** `app/retrieval/{scope,query_embed,vector,lexical,fusion,rerank,expand,retrieve,load,config}.py`. The config is `backend/config/retrieval@N.yaml`, a strict schema with a new file per change.
- **Chat**
  - Evidence and citations:
    - `app/chat/evidence.py`: `build_evidence` creates handles E{k}.{i}; `answer_schema` uses an enum of handles, falling back to strings above 1,000 handles.
    - `app/chat/citations.py`: `resolve` copies `cited_text` by code.
  - Nodes: `app/chat/nodes/{analyze,generate}.py`
  - Orchestrator: `app/chat/turn.py`, `run_turn` → `_run_turn`, with a lease heartbeat and a persist fallback.
  - Ledger: `app/chat/ledger.py`, `persist_turn` (one transaction).
  - History: `app/chat/history.py`. Sessions: `app/chat/sessions.py`. Turn budget: `app/chat/harness.py`, `TurnBudget`.
- **Insights:** `app/insights/{brief,verify,stage,views,summaries,staleness}.py`
- **LLM**
  - Gateway: `app/llm/gateway.py`, the **only** way to call a model. It has `call` (schema), `stream`, `embed`, and is built with `build_gateway(sessionmaker)` or `get_gateway()`.
  - Prompts: `backend/prompts/<id>@<v>.md` with front-matter (role, effort, output, max_tokens).
  - Roles: fast, balanced, deep, flagship. Model names live only in settings and `app/llm/routing.py`.
- **Tests**
  - Layout: `backend/tests/{unit,integration,e2e,live}`
  - Fixtures: `tests/integration/conftest.py` (the `api`, `sm` and `make_owner` fixtures; the turn runner is a no-op by default and tests override `get_turn_runner`). Chat-specific fixtures, including `ledger_owners`, are in `tests/support/ledger_env.py`.
  - Support helpers: `tests/support/*`. FakeProvider: `app/llm/providers/fake.py`.
- **Eval**
  - Harness: `eval/{run,schema,loader,mapping,graders,report,baseline,judge,replay,pipeline_retrieval,pipeline_http,brief_eval}.py`
  - Engine: `eval/engine/*`. Golden set: `eval/datasets/vault_eval_v1/`.

## 8. Known gotchas (each one cost time before)

1. **FakeProvider's script queue:** `embed()` pops a scripted step from the same queue as chat calls. In end-to-end turn tests, insert a placeholder step (`EMBED_SLOT = structured({})`) where the query embedding happens.
2. **Turn runner in tests:** the integration `api` fixture overrides `get_turn_runner` with a no-op, so POST /messages returns 202 `running`. Tests that need a finished turn override it (see `tests/integration/chat/test_turn_e2e.py`).
3. **Chunk sentences in DB:** stored as `[[start, end], ...]`. Some old test seeds use dicts; `app/retrieval/load.py::_sentences` accepts both.
4. **Flow documents (DOCX/TXT/MD)** have `page_start = page_end = 0`, meaning no pages. Never display page 0.
5. **Postgres full-text:** `tsv_en` is a generated column over `embedding_text`. Changing `embedding_text` changes lexical search too.
6. **Lint:** line length is 110; `S608` flags f-string SQL, so interpolate constants only and add a `# noqa: S608 (reason)`. mypy runs in strict mode.
7. **Reranker container:** runs on Linux arm64. `os.cpu_count()` inside a container reports the VM's CPUs, not the quota. Use `RERANKER_THREADS`.
8. **`.env.example`:** a test requires every Settings field to appear in it. Add any new setting to both.
9. **Celery:** every task name must appear in `app/worker/celery_app.py::ROUTES`, or a unit test fails.
10. **Don't hold a DB connection across an LLM call or a reranker call.** End the transaction first (`await session.rollback()` after reads), or open a new short session per phase.
11. **Makefile `CONFIG`:** it is used by the otel target. Retrieval evals use `RETR_CONFIG`.
12. **Live tests:** marked `@pytest.mark.live`, excluded from `make test`. Run them explicitly with `-m live`.
