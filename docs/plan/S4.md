### S4.18 — Stage D: prompt hill-climb loop
Deps: S4.17, S2.14, S2.15, S2.16, S4.16 · Design: research 06 §3 · Files: `eval/engine/stage_d.py`, `backend/prompts/eval_analyzer@1.md`
Do: Each round: attribute train failures → if the largest bucket belongs to stage D, a fresh-context analyzer reads **train** transcripts only and proposes one generalizable prompt change → apply as a new prompt version → frozen-evidence replay on smoke, then train+test (reps=2, Batch mode) → accept iff the paired test delta exceeds the noise floor and guardrails hold, else revert. Stops on targets met, plateau (K=3), or budget.
- [ ] AC1 Analyzer inputs contain no test-split item IDs or test document text (verified on the recorded inputs) — `t:unit/eval/test_stage_d.py::test_no_test_leakage`
- [ ] AC2 A proposed prompt diff containing any 5-gram from train gold answers is rejected — `t:unit/eval/test_stage_d.py::test_memorization_lint`
- [ ] AC3 A round with train up and test flat is reverted (simulated) — `t:unit/eval/test_stage_d.py::test_revert_on_test_flat`
- [ ] AC4 A round breaking a guardrail (citation integrity < 100%, cost +25%, p50 latency +20%) is reverted even if quality improves — `t:unit/eval/test_stage_d.py::test_guardrail_revert`
- [ ] AC5 Each accepted change bumps the prompt version and logs it to `AI_USAGE.md` with its eval delta — `t:unit/eval/test_stage_d.py::test_version_and_log`
