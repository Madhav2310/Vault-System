# S17 — Retrieval and answer quality (plan v3)

Goal: answers are right more often, cite exactly, flag anything unsupported, and say "not found" when the documents don't answer. Every change is an A/B on the **train** split with a paired statistical test, confirmed once on **test**. Targets:

| Metric | Target |
|---|---|
| retrieval recall@8 (train) | ≥ 0.85 |
| answer pass rate | ≥ 0.80 |
| citation integrity | 1.00 [A] |
| smoke abstention precision | ≥ 0.80 |
| p50 latency, non-streaming | ≤ 4 s |

Read `docs/plan/v3.md` first. Every live run uses `--max-usd`. Run the A/Bs one at a time (machine load).

Carried from v2: S11.03 AC8 → S17.02; S11.04 → S17.04; S11.05/S11.06 → S17.02/S17.03/S17.06; S11.08/S11.11 → S17.10; S11.10 → S17.08; S11.12–S11.15 → S17.11; S13.10 → S17.12. S11.07 and S11.09 (speculative retrieval) are dropped: the fast path covers most of the latency win at a fraction of the complexity.

### S17.01 — Paired statistics for A/B decisions
Deps: S16.07 · Design: §18 · Files: `eval/report.py`, `eval/paired.py`, `backend/tests/unit/eval/test_paired.py`
Do:
1. `eval.run` writes a JSON sidecar `eval/reports/<run_id>.json` next to the markdown. It holds `{run_id, name, suite, split, git_sha, config, items: [{item_id, category, metrics: {...}, quote_hits: {"8": [bool...]}}]}`. `quote_hits` is the per-quote hit list at k = 8; add it to the retrieval metrics output in `eval/graders.py::retrieval_metrics` as an extra non-metric field kept on `ItemResult`.
2. `python -m eval.paired A.json B.json --metric recall@8 [--seed 7]` prints:
   - n paired items and the means of A and B
   - delta = B − A
   - the 95% paired-bootstrap CI of the delta (10,000 resamples over items, fixed seed)
   - McNemar exact p-value on per-quote hits, using the discordant counts b01 and b10
   - a verdict:
     - `B better` when CI_low > 0 and p < 0.05
     - `B worse` when CI_high < 0 and p < 0.05
     - `no detectable difference` otherwise
3. Items present in only one run are excluded; their count is printed.

### S17.14 — Explicit turn graph: conditional nodes, a node runner, intra-turn concurrency
Deps: S16.07 · Design: §5.1 (`chat.harness`), §8.1, §8.2 · Files: `backend/app/chat/graph.py`, `backend/app/chat/nodes/*.py`, `backend/app/chat/turn.py`, `backend/app/retrieval/retrieve.py`, `backend/tests/unit/chat/test_graph.py`, `backend/tests/integration/chat/test_turn_concurrency.py`
Why: `turn.py` routes with inline if/else and runs every step sequentially (5.9 s p50: analyze 2.0 s → embed 0.5 s → vector → lexical → rerank → generate 2.1 s). S17.07–S17.10 and S18.05–S18.06 add about six more branches. This is a small, dependency-free graph in the spirit of LangGraph (typed state, nodes, conditional edges, step records), **not** LangChain or LangGraph themselves. Research: own your control flow; frameworks hide prompts and control flow.
Do:
1. **`graph.py`** (≤ 200 lines, no new dependency):
   - `TurnState`: a dataclass holding question, memory, scope, analysis, retrieval, evidence, generation, verdicts, reasons, degraded and mode.
   - `Node = Callable[[TurnState, TurnCtx], Awaitable[TurnState]]`.
   - `Router = Callable[[TurnState], str]`: the name of the next node, or `END`.
   - `Graph(nodes: dict[str, Node], edges: dict[str, str | Router], start: str)`.
   - `run(state, ctx) -> TurnState` executes nodes in order:
     - **Per node:** an OTel span `vault.node.<name>`, `asyncio.timeout` from the turn budget's remaining time, and a `StepRecord` appended automatically (status ok, failed or timeout; `duration_ms`; `decision` from the node's returned `state.last_decision`). An exception becomes a failed step and the turn ends with an error response: the existing persist path, never a stuck run.
     - **Loop guard:** at most 12 node executions per turn; above that, end with `TURN_ERROR`.
   - `describe() -> str` returns a Mermaid flowchart of nodes and edges, with routers drawn as diamonds and their possible targets taken from a declared `targets` list. S20.02 uses this to generate the turn diagram **from code**.
2. **Port the current `turn.py` logic into nodes**, one function per file in `app/chat/nodes/`: `load_context` (session, scope, memory), `route_question` (the fast-path rules from S17.10 live here once that lands; until then always `analyze`), `analyze`, `retrieve`, `gate`, `generate`, `verify`, `persist`. Routers:
   - after `load_context`: empty scope → `abstain_no_documents`
   - after `analyze`: clarification → `clarify`; meta → `meta` (S18.05 adds it); otherwise `retrieve`
   - after `retrieve`: no evidence → `abstain_no_evidence`; otherwise `gate`
   - after `gate`: below the floor → `abstain_no_evidence` (S17.08 fills the floor); otherwise `generate`
   - after `generate`: any cited segment → `verify`; otherwise `persist`

   Behaviour must be identical to today for every path covered by the existing tests. Run them unchanged.
3. **Intra-turn concurrency**, each in its node:
   - **Embed while analyzing.** When `analyze` runs, start the query embedding of the raw question at the same moment (`asyncio.gather`). After analysis, reuse the vector if the standalone query equals the question after `normalize_query`, otherwise embed again (cached by key). The `Retriever` accepts an optional precomputed `QueryEmbedding`.
   - **Vector ∥ lexical.** In `Retriever.retrieve`, run `vector_search` and `lexical_search` concurrently on **two separate short sessions** from the sessionmaker. One `AsyncSession` cannot run concurrent statements. The Retriever takes a sessionmaker instead of a session; update all callers.
   - **Load passages while the vector search runs** if it fits naturally; otherwise skip this item. Correctness first.
4. **No DB session held across an LLM or reranker call** (gotcha 10). A test checks pool `checkedout()` during a FakeProvider latency window.
5. **Retrieve sub-step timings** (`embed_ms`, `vector_ms`, `lexical_ms`, `rerank_ms`, `expand_ms`) go in the retrieve step decision (S17.10 AC5 relies on this).
